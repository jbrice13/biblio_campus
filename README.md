# 14) Grille de travail proposée

## Semaine 1
- mise en place du dépôt,
- configuration Git,
- structure de base,
- création des branches.

## Semaine 2
- gestion des livres,
- menu principal,
- premiers commits.

## Semaine 3
- emprunts et retours,
- statistiques,
- synchronisation entre branches.

## Semaine 4
- résolution des conflits,
- nettoyage du code,
- finalisation du README,
- push final.

# 15) Évaluation possible

## Critères techniques
- dépôt correctement structuré,
- branches bien utilisées,
- commits clairs,
- conflits résolus proprement,
- code Python fonctionnel,
- synchronisation avec le dépôt distant.

## Critères collaboratifs
- respect des rôles,
- répartition équilibrée du travail,
- communication entre les membres,
- bonne gestion des merges.

## Critères de qualité
- lisibilité du code,
- qualité du README,
- respect de l’arborescence,
- propreté de l’historique Git.

# 16) Variantes pédagogiques

## Variante 1 : GitHub
Utiliser pull requests, branches de fonctionnalité et revue de code.

## Variante 2 : GitLab
Utiliser merge requests, issues et tableau de bord de projet.

## Variante 3 : conflit volontaire renforcé
Faire modifier le même fichier par deux branches différentes pour forcer un conflit réel.
